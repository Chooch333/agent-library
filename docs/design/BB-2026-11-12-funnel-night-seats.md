Logging decisions stays as it is; the block cites them. Replaces night-run step 4's bare "Forks: decide and log".
2. **One seat step, two uses** (`skills/night-run`, new section "Seat step"): seats are c-stack plus the one craft under it whose call_when best matches (two seats; one when the work sits in one corner), mode full, through the Expert Desk (`skills/expert-desk`) run by the night session itself, seat prompts from its seat template with "Already decided" = the brief's Decisions. The desk files its report as one note on the plan's project (tag `expert-desk-report`).
   - **Before the build (new step 3a):** if the plan's provenance has no line `Seated: revision <N>, report <note id>, seats <slugs>` matching its current revision (`get_plan` → `current_revision`), run the seat step on the brief; apply the room's path as a revision (`update_plan_content`, change_reason "pre-build expert seat: <one line>"), add tag `experts-seated` and the provenance line for the new revision, then build. A brief seated at an older revision is seated on the change only.
   - **After the build (new step 5a, after step 5's landed check, before the `built` row and before step 6):** read the handoff back first (`list_commits` on its branch, blob SHAs from the directory listings — the handoff is a claim, not proof); run the seat step on the handoff plus the commits it names (seats open the commits; the decision list is an index).
3. **Revision loop (step 5a, continued):** each objection is a revision instruction. A fresh builder helper gets the brief, the handoff and the instructions; it re-reads every file at the branch head (a blob SHA differing from the handoff means another writer: re-read and layer on top), commits forward only (no force, no branch ops) with the repo's markers (cbrain-ui `[wip]` then a final `[deploy]`; cbrain `[skip ci]` on all but the last; one commit per file elsewhere), re-runs every acceptance check the revision touches, and files a revision note on the plan's project (tag `night-revision`: commits, checks, evidence). Then the deploy re-check on the revision's head SHA. Round two re-seats only the objecting seat on the revision. Cap two rounds. The done receipt stands for the first version; the revision note is the record for the next.
4. **Never on Charles:** a revision whose checks fail, whose deploy goes red, or that hits a hard stop is undone by a forward commit restoring the handoff's blobs; the round counts. A seat that fails: the build stands as built. The disagreement left after round two, a reverted revision, or a failed seat becomes **one `lens-note` for the objecting expert** on `expert-bench` (tags `lens-note`, `expert-<slug>`; text names the plan, the objection, what was tried) — read by every later seat of that expert and folded or routed on Sunday. Then log `built` with a trace line: "built · seated: <slugs> · revisions <n> applied, <m> reverted · leftover <k>". None of these is `deploy-red`, `stuck` or `interrupted`; none opens a card or an email. Only the five hard stops (money, a credential only he holds, irreversible, safety, a settled rule) stop a build, as today.
