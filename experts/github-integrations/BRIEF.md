# github-integrations

GitHub used as a worker and as a store: workflows, dispatch, concurrency, branches, commits and repo-folder queues. Where a job runs belongs to lanes. MCP tool rollout and keys belong to services. Dot checks and reporting belong to oversight.

## Our way

1. Graph writes: every graph-writing run joins the one concurrency group `falkordb-writer`, never cancelled, and applies all unapplied work, so a waiting run that gets dropped loses nothing; not one group per workflow, because two runs would load and commit the same saved graph [stack-map world-graph dot; CB-406 item 5]
2. Schedules: Actions timers stay off since 2026-10-12. Only the nightly run fires on its own, and its missed-work sweep starts any waiting jobs; everything else runs by hand; not a push trigger or schedule added to make one job run on its own, because that routes around the switch-off (the rule is c-stack's Our way 6) [stack-map schedule comments; SM-079; CB-562]
3. Dispatch: `run_workflow` with an explicit ref and every input passed, after reading the workflow file for its defaults; a new dispatchable workflow is committed to the default branch first. Not a default trusted, because workflows that look alike default to different targets [CB-210; CB-173; CB-144]
4. Missed runs: after an outage, dispatch by hand whatever was pushed in the meantime, after checking the ledger for what the thawing run already applied; not waiting on push triggers, because they never replay [CB-438; CB-512; gotchas]
5. A failed run: read `get_workflow_run` and `get_job_logs` first. Zero steps, ending in seconds, is the billing lock: a hard gate, no re-runs. Zero steps, cancelled after a long wait, is a runner hiccup: dispatch again with an explicit ref. Not re-run blind, because the log is readable and every run costs minutes [A-092; CB-550; CB-520]
6. Chaining: one workflow starts another by explicit dispatch or `workflow_run`; not a trigger on the same push, because the first run's commit-back lands later [WG-051]; ~ field default: a push made with the workflow's own token starts no run [GitHub events docs, read 2026-11-03]
7. cbrain-ui branches: builds land on `review`, and `main` is only what is live; app code is read with `ref: review`; promotion is the go-live fast-forward. Not a direct patch to `main`, because fast-forward-only promotion then refuses [CB-159; CB-185; CB-530; CB-528]
8. Branch operations: through `branch-ops.yml`, which only creates a branch or does a guarded fast-forward; not a force mode or extra modes on a scratch workflow, because a force-sync is Charles's call, not a button [CB-168]
9. Every write: `branch` passed on each write tool, and each commit read back (sha, size, the text around the edit); not the tool's success reply trusted, because write tools default to `main` and wrong edits land silently [CB-233; E-192]
10. Large files: anchored `replace_in_file` edits on the smallest unique anchor (generated by a script when there are many), each read back; a whole-file write only for small files, or for regex-heavy code compiled locally first; not one inline commit of a large file, because it times out [E-196; E-189; D-056; SM-091]
11. Commit order: every commit is a build, so a paired change goes in one commit, or the consumer goes first; not the declaration first, because the in-between commit breaks the deploy [F-088; E-196; TH-038]
12. Commit markers: commits to cbrain-ui `review` carry `[wip]`, and checkpoints carry `[deploy]`; a many-commit write anywhere else puts `[skip ci]` on every commit but the last. Not one build or CI run per commit, because that burned build minutes and Actions minutes [checkpoint-deploy 0.2; SM-091; CB-550]
13. Collisions: "already exists" or a 409 means another writer got there first: stop, re-read, then adopt the work if it is faithful or layer yours on top; not overwrite [C-061; WG-085]
14. Repo-folder queues: one file per item, named from a hash of its source, written once (skipped if it already exists), its status flipped in place, every write read back. Not a Project State project used as a queue, because that mixes work with the record [post-reader steps 2e–2g; skill-design-framework Q5]
15. A container in a workflow that commits the container's files: pinned by digest, its mount handed back to the runner user before the commit; not `:latest`, because an image update changed file ownership and stranded the graph writes [CB-543]
16. History rewrite: only on Charles's call. Pull the latest right before, force-push with lease, and re-enable any workflow disabled for the rewrite before closing; not from a stale clone, because it erases concurrent builds' commits [gotchas; CB-505; CB-502]
17. Commits with nobody present: a scheduled run commits through the GitHub connector and reads each write back; not raw `git push`, because scheduled cloud sessions found no git credentials [post-reader steps 2e–2g; TH-126; TH-128; ~ one probe, TH-132, cloned fine but could not prove push]

## Lens

1. Silence read as success: Actions goes dark through the billing lock or a disabled workflow (dispatch refused, no run created), and nobody lists recent runs before trusting a trigger [gotchas; CB-427; CB-502]
2. A concurrency group trusted to hold every waiting run: by default one run waits, and an older waiting run is cancelled when another queues [GitHub concurrency docs, read 2026-11-03; CB-406 item 5]
3. Two builds editing one repo or file at once: a 409 race mid-build, or branches that fast-forward-only merges cannot reconcile [c-stack 17; WG-085; CB-291]
4. A large matched block replaced, silently deleting what sat inside it, or an anchor swallowing the opening of the next block [CB-045; E-192]
5. A regex or `$` inside a `replace_in_file` new text corrupting the whole file [E-189]
6. A file move assumed byte-safe through content-based tools; it is not [E-150]
7. A `search_code` miss taken as proof: the index lags a push, covers only `main`, and returned nothing on the private repos [A-070; CB-258; TH-064]
8. A token whose scopes look right in the dashboard but fails on a real dispatch; recreating it fixed it, editing did not [CB-138]
9. An evidence file overwritten in place by date, then read as this run's result [CB-210]
10. A long freehand comment block written in an edit, breaking the build while the write tool reports success; the deploy state is the compile check [CB-233; E-168]
11. A schedule trusted to fire on time: schedules run only on the default branch and can be delayed or dropped under load [GitHub events docs, read 2026-11-03]
12. `[skip ci]` expected to stop a dispatched or scheduled run; it only applies to push and pull-request events [GitHub skip docs, read 2026-11-03]
13. A run of the Claude Action started by a bot is refused unless that bot is allowed [A-064; ~ the workflow it hit, repair.yml, was deleted 2026-10-23]
14. A Node `fetch()` step failing on runners over IPv6 while curl steps pass [CB-144]
